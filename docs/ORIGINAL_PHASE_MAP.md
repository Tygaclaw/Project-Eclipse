# Canonical ECLIPSE Phase Map

The original ECLIPSE v3.0 Master Plan (25-page PDF, dated 3 November 2026) defines **nine numbered core stages, Phases 1–9**, bracketed by Phase 0 and Phase 10. The later unified handoff expands delivery to Phase 0–11. These two maps are related but not interchangeable.

## Original model-engineering stages

| Original phase | Name | Exit evidence |
|---|---|---|
| 0 | Foundation and hardware profile | Historical hardware/tool audit and baseline recorded; do not repeat as a generic setup prerequisite |
| 1 | Model Intelligence Laboratory | Bounded GGUF/Safetensors/config inspection, Atlas and real oversized-checkpoint validation |
| 2 | Feasibility and compatibility planner | Evidence-labelled storage/RAM/VRAM/KV/backend report; no invented token-speed prediction |
| 3 | Lossless preparation | Reproducible indexes/manifests/checksums; original untouched |
| 4 | First inference foundation | One proven backend/model path with measured correctness, latency and resource use |
| 5 | Fast-path optimization | Sustained measured benefit from placement, movement, cache/prefetch; no routing substitution or thrashing |
| 6 | Runtime model intelligence | Backend-supported observed access/routing telemetry with overhead measurement |
| 7 | Advanced compression | Reproducible quality/size/speed trade-offs against baseline |
| 8 | NECS and Capability Watchdog | Optional sidecar held-out benefit plus task-level watchdog verification; do not conflate the two |
| 9 | Externalized intelligence | Project memory, tools, execution and verification workflow with safe boundaries |
| 10 | Complete ECLIPSE Desktop | Installable Windows desktop, profiles, resource manager, diagnostics and recovery |

## Expanded integrated delivery roadmap

| Integrated phase | Focus | Relation to original stages |
|---|---|---|
| 0 | Historical foundation | Original Phase 0; completed history preserved |
| 1 | Project control plane and repository | Engineering governance and stack choice |
| 2 | Requirements, architecture and experience shell | Shared Core and three workspaces |
| 3 | Static Model Intelligence Laboratory | Original Phase 1 |
| 4 | Feasibility, compatibility and lossless preparation | Original Phases 2–3 |
| 5 | First model runtime and registry | Original Phase 4 |
| 6 | Capability amplification core | Original Phase 9 plus watchdog foundations from Phase 8 |
| 7 | Obsidian, memory and skills | Externalized knowledge integration |
| 8 | Advanced reasoning and benchmarks | Evaluation and capability verification |
| 9 | Fast-path inference and predictive memory management | Original Phases 5–6 |
| 10 | Advanced compression, runtime intelligence and NECS research | Original Phases 7–8 |
| 11 | Complete desktop and release | Original Phase 10 productization |

The historical Qwen discussion also proposes a six-step initial sequence: prove the existing tool connection, establish baseline, build the ECLIPSE core, add advanced workflows, evaluate/improve, then pursue model-level optimization. This is useful sequencing context, not a replacement for either phase map.
